# Checklist de release — v1.0.0

**Estado:** Pendiente de aprobación  
**Responsable de QA:** Henry Alvarez  
**Tag objetivo:** `v1.0.0`

Esta checklist debe completarse antes de crear el tag. Una casilla pendiente impide declarar la línea base como liberada.

## Alcance y trazabilidad

- [ ] El alcance de la versión y los cambios incluidos están registrados.
- [ ] Los issues/RFC, PRs y commits de la versión están enlazados.
- [ ] Los EC modificados y su impacto están revisados.
- [ ] `CHANGELOG.md` contiene las notas de versión verificadas.

## Calidad

- [ ] CI de backend aprobada: restore y build `Release`.
- [ ] Pruebas .NET existentes ejecutadas y aprobadas, o se documentó formalmente su ausencia.
- [ ] CI de frontend aprobada: instalación reproducible, build y Karma en ChromeHeadless.
- [ ] Flujos críticos validados: autenticación, inventario, facturación y reparaciones.
- [ ] No hay secretos, llaves ni archivos locales en el diff de release.

## Datos, configuración y despliegue

- [ ] Migraciones EF Core y scripts SQL revisados y probados en una base temporal.
- [ ] El orden de ejecución de scripts, incluidos triggers, está documentado.
- [ ] Las variables de `.env.example` están actualizadas y no contienen valores reales.
- [ ] Las cargas de `wwwroot/uploads` están clasificadas como fixtures o datos operativos con respaldo definido.
- [ ] Docker y/o el procedimiento de despliegue fue validado en un entorno limpio.

## Aprobación y publicación

- [ ] PR de release integrado en `main` y árbol de trabajo limpio.
- [ ] Henry Alvarez aprueba la evidencia de QA.
- [ ] Se crea el tag anotado `v1.0.0` sobre el commit aprobado.
- [ ] Se publica el tag y un GitHub Release con sus notas.
